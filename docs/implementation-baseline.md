## 2. Current architecture and process boundaries

Four processes. The boundaries are the security design, so they are stated as
boundaries rather than as a component list.

```
┌─ Process 1: Tauri desktop app ────────────────────────────────────────┐
│                                                                       │
│  WebView (React 19 + TS, src/)                                        │
│    - typed service wrappers in src/services/ → invoke()               │
│    - no policy logic; renders what Rust decided                       │
│              │ Tauri IPC (96 registered commands)                     │
│  Rust core (src-tauri/, crate `sarathi`)                              │
│    - policy::PolicyGateway        the only thing that decides         │
│    - orchestrator::gateway        validates the call shape            │
│    - sovereignty::broker          the only outbound HTTP client       │
│    - knowledge / documents / artifacts / registry / audit             │
│                                                                       │
│    ├─ inbound  127.0.0.1:<port>  axum "gateway" (OpenAI + Anthropic)  │
│    └─ outbound (Provisioning mode only, allowlisted hosts)            │
└───────────────────────────────────────────────────────────────────────┘
        │ stdio, newline-delimited JSON-RPC        │ stdio JSON
        ▼                                          ▼
┌─ Process 2: agent runtime ──────┐   ┌─ Process 3/4: Python sidecars ──┐
│  node agent-runtime/dist/       │   │  document_sidecar (Docling /    │
│    arjun-agent-runtime.mjs      │   │    text-layer, injection scan)  │
│  vendored OpenClaw agent loop   │   │  memory_engine_sidecar          │
│  opens no listening socket      │   │  opens no socket                │
│  reaches only the loopback      │   └─────────────────────────────────┘
│    inference endpoint            │
└──────────────────────────────────┘
        │ HTTP (loopback, OpenAI-compatible)
        ▼
   llama-server / Python model server (started by `serving/`, or operator-run)
```

### The authority split

`src-tauri/src/agent_runtime/mod.rs` states it and the code holds it: **the
runtime may request; only Rust decides.** The Node process serves no policy. It
asks two questions over the wire:

- `tool.authorize` — put through `ToolGateway` → `PolicyGateway`. An allow
  returns a single-use opaque **grant** bound to `(run_id, tool_call_id, tool,
  SHA-256 of args)` with a 60s TTL (`agent_runtime/grants.rs`).
- `tool.execute` — redeems the grant **and independently re-derives the verdict**
  (`agent_runtime/mod.rs`). Two checks: the grant covers a compromised runtime,
  the re-check covers a bug in the grant.

`agent-runtime/src/tools.ts` installs authorisation as a loop hook
(`beforeToolCall`), not a per-tool method, so a tool added later cannot forget to
authorise itself. Authorisation failure fails **closed** — an unreachable gateway
becomes `{ block: true }`, not an assumption of consent.

### Process hardening already in place

- `agent-runtime/src/main.ts` rebinds `console.*` to stderr so a stray log from
  any vendored dependency cannot desynchronise the stdout frame channel; a
  malformed frame is fatal (`process.exit(70)`) rather than recoverable.
- `agent-runtime/src/run.ts` `assertLoopback()` refuses any non-loopback
  `baseUrl` before a socket opens.
- The Rust supervisor strips `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/etc. from the
  child's environment and uses `kill_on_drop`.
- Tool **arguments** are stripped from the event stream in both directions
  (`redactEvent` in run.ts; redaction in `agent_runtime/events/model.rs`).

## 3. Existing working features

"Working" here means: exercised by a test that runs locally, or wired end to end
from the UI to a deterministic result. Claims that rest only on prose are in §4.

### 3.1 Sovereignty and egress proof — working

- Two modes, `OperatingMode::{Provisioning, Work}`, defaulting to **Work**
  (`sovereignty/mode.rs`). `permits_network()` and `permits_confidential_data()`
  are exact complements; the invariant is that they are never both true.
- `sovereignty/broker.rs` is the only module permitted to construct an outbound
  `reqwest::Client`. It enforces mode, `https` only, exact-match host allowlist
  (`huggingface.co` + two CDN hosts — the entire external surface), and refuses
  to follow redirects at all.
- Every decision, permitted and refused, is recorded to an in-memory ring (512)
  and to the durable audit log.
- `run_canary()` deliberately attempts a call that must fail, through the real
  `evaluate` path, so a bug that opened the door shows up as a canary *pass*.
- `sovereignty/observer.rs` independently queries Windows `GetExtendedTcpTable`
  for this PID's TCP connections — corroboration from outside ARJUN's own
  bookkeeping. Its documented scope limits (TCP only, this process, poll-interval
  gaps) are stated in the module rather than glossed.
- `scripts/check-egress.mjs` fails the build if a second HTTP client appears or
  an unreviewed hostname enters the tree; exemptions need a self-documenting
  `arjun-egress-ok: <reason>` comment.
- **UI:** `src/pages/AuditNetwork.tsx` polls mode, egress events and OS-observed
  connections every 2s and can fire the canary.

### 3.2 Policy, approval and path containment — working

- `policy/mod.rs` decides in a fixed order: sovereignty invariant → entitlement →
  classification clearance → path scope → separation of duties → approval state.
  It is a pure function over `(Session, Request, bool)`; the broker is *passed in*,
  not reached for.
- Seven site-specific classifications (`Internal`, `ProcessDiagram`, `Financial`,
  `VendorNegotiation`, `UnreleasedDesign`, `InternalCorrespondence`,
  `BusinessStrategy`) with per-role clearance. The `Auditor` role is deliberately
  cleared for none — it reads the record, not the documents.
- Path containment (`orchestrator/gateway.rs::resolve_within`,
  `policy/mod.rs::is_within`) resolves `..` **textually**, refusing rather than
  clamping. Textual because the write target usually does not exist yet, and
  because it cannot be defeated by a symlink planted between check and write.
- `agent_runtime/mod.rs::anchor_path` anchors purely-relative paths to the run's
  workspace before the gateway sees them, while passing rooted/absolute paths
  through to be judged as written (so `join()` cannot silently escape on Windows).
- Approval is real end to end: `NeedsApproval` → `approval::await_decision` →
  `ApprovalQueue` → `src/pages/Approvals.tsx` → `decide_approval`. Approval
  requires `Permission::ApproveOutput`, which `Administrator` deliberately does
  **not** hold. A rejection requires a written reason.
- Per-run workspaces (`agent_runtime/workspace.rs`, `app_data/runs/<run_id>/`) —
  per run, not per process, so one task cannot read another's leftovers.

### 3.3 Model routing — working

- `registry/router.rs`: classify prompt → confidence floor 0.55 → filter to
  enabled candidates of the right role and clearance → prefer largest that fits
  VRAM → fall back to partial-CPU rather than failing.
- Low confidence routes to `Reasoning` deliberately (a general model handles a
  coding question adequately; the reverse is worse).
- `RoutingDecision` carries ordered human-readable `reasons`, shown verbatim in
  the run trace. Six roles exist: Reasoning, Coding, Vision, DocumentOcr,
  Embedding, Rerank.
- The UI cannot name a model. `StartRunRequest` has no model field, by design.

### 3.4 Agent execution — working

- Bounded plans (`orchestrator/plan.rs`): 12 steps, 10 minutes, repeat limit 3,
  and an explicit permitted-tool set fixed before the model is told anything.
  `StopReason` distinguishes Completed / StepsExhausted / TimeExhausted / Looping
  / AwaitingApproval / Failed.
- Context compaction (`agent-runtime/src/compaction.ts`) using OpenClaw's
  cut-point logic, so a tool call is never separated from its result.
- Steering (`run.steer`) applies a correction at the next safe point without
  losing gathered tool results.
- Durable run history (uncommitted, see §1): ordered append-only SQLite events,
  snapshots, restart recovery, and idempotency keys for side-effecting tools.

### 3.5 Deterministic calculation — working

`orchestrator/calculation.rs` (649 lines) evaluates unit-bearing expressions and
records every step. The engine owns the figure; the model quotes it. `create_xlsx`
renders the run's *recorded* calculations as live Excel formulas rather than
taking figures as arguments — so the workbook cannot contain a number the engine
did not produce.

### 3.6 Retrieval with citations — working (keyword only)

- `knowledge/index.rs` — SQLite FTS5 with BM25. Search is **ACL-filtered in SQL**:
  the `WHERE c.classification IN (...)` list is built from the session's cleared
  classifications, and a user cleared for nothing gets an empty result
  indistinguishable from "nothing matched".
- Passages carry document name and page; markers `[E1]`, `[E2]`… are numbered
  once across a run (`agent_runtime/retrieval.rs`) so a citation means one passage.
- Chunking is structure-aware (`knowledge/chunking.rs`).
- Connector reads a local folder or internal share, read-only
  (`knowledge/connector.rs`).

### 3.7 Artifact generation and verification — working

- `.docx` / `.xlsx` / `.pptx` written by composing OOXML parts directly
  (`artifacts/{docx,xlsx,pptx,ooxml}.rs`) — no document library, so the structure
  is reviewable in-repo.
- Every produced file is **re-opened and checked** rather than taken on the
  model's word (`agent_runtime/artifacts.rs::check`). A run whose document does
  not re-open is not `ready`.
- Documents are stamped DRAFT on the page until a person signs them.
- `artifacts/verifier.rs` resolves every `[En]` against passages actually
  retrieved and every figure against calculations actually run. It does **not**
  edit or withhold the draft — it downgrades standing from `ready` to
  `needsReview` and attaches findings.

### 3.8 Audit — working

`audit/mod.rs`: append-only enforced by SQLite triggers (not convention), plus a
SHA-256 hash chain over `(prev_hash, seq, at, actor, kind, summary, detail)`.
`verify_chain` reports the first broken sequence number. Reads and writes happen
inside `BEGIN IMMEDIATE` so two writers cannot claim one predecessor.

### 3.9 Identity — working

Argon2id password hashing with per-password CSPRNG salts
(`identity/credentials.rs`), six roles, permission sets per role, and
separation-of-duties enforced in policy rather than in the UI.

## 4. Existing refusal-only or placeholder features

These are the honest gaps. Several are refusal-only **by design and say so** —
that is a deliberate and defensible position, not a defect — but they are not
working features and must not be described as such.

### 4.1 `execute_code` — refusal-only in every branch

`orchestrator/runner.rs::execute_code` returns `Err` twice over:

- If `sandbox::assess` refuses (no container runtime): *"Code was not run: …
  Nothing was executed, so no result exists — do not describe what the code would
  have produced."*
- **If the machine *could* isolate it:** *"Running code is not implemented yet,
  even though this machine could isolate it. No result exists."*

`orchestrator/sandbox.rs` is a real, thought-through tier model
(Container → WSL2 → JobObject → None) that correctly refuses when the promise
that matters (network blocking) cannot be kept. What is missing is the executor
itself. The tool description in `agent-runtime/src/tools.ts` tells the model so
explicitly.

### 4.2 OCR / VLM — planned, not present

- `sidecars/document_sidecar/` has exactly two engines:
  `DoclingEngine` (if importable) and `TextLayerEngine` (fallback).
  `ENGINE_PREFERENCE = [DoclingEngine, TextLayerEngine]`. **There is no OCR
  engine and no vision engine.**
- `escalation.py` correctly *plans* a second expensive pass over low-confidence
  pages (`CONFIDENCE_FLOOR = 0.5`, `SUSPICIOUSLY_SHORT = 24`) and is explicitly
  written to produce a sensible answer when no vision engine exists — it names
  what each page needs so the gap is visible. Nothing consumes that plan.
- `ModelRole::{Vision, DocumentOcr}` exist in the registry with capability
  weights of 1.0 and 0.0, but no such model is provisioned.
- Consequence: a scanned page, drawing or photograph is read as low-confidence or
  empty and flagged for review. It is never *read*.

### 4.3 Workbench attachments — UI only

`src/pages/Workbench.tsx` collects attachments, and correctly refuses them when
the sovereignty invariant says confidential material may not be handled. But
`onFilesPicked` keeps only `f.name` — file **names**, not contents — and
`submit()` calls `start(asked)` with the prompt alone. **No attachment ever
reaches the backend.** There is no per-task document ingestion path.

### 4.4 Injection-defence layer 3 is dead code

`knowledge/evidence.rs` implements the untrusted-data framing ARJUN design rule 23 asks for
— a long unguessable delimiter pair (`<<<ARJUN_EVIDENCE_BEGIN>>>`) and a preamble
telling the model the block is data, not instructions.

**`evidence::present` has no callers.** The live path is
`LocalToolRunner::search_hits` → `retrieval::record` →
`orchestrator/runner.rs::render_passages`, which emits raw passage text with no
delimiters and no preamble.

The module itself is candid that this is the weakest of the three layers and that
the gateway is the one that actually holds — which remains true. But the layer is
currently absent, not weak.

### 4.5 Vector / hybrid retrieval — unwired

`knowledge/hybrid.rs` (`Embedder`, `Hybrid`, `reciprocal_rank_fusion`) is
re-exported in `knowledge/mod.rs` and referenced nowhere else. Live retrieval is
BM25 keyword search only. No embedding model is provisioned.

### 4.6 Checkable task package — proven by test, unreachable from the UI

`package/mod.rs` implements ARJUN design rule 33 in full: a plain ZIP of JSON plus the
artifact, every entry SHA-256'd in `manifest.json`, the manifest's own hash
returned for out-of-band recording, verifiable with `unzip` and `sha256sum`
alone. **Its only callers are `src-tauri/tests/baseline.rs`.** No Tauri command
exposes it.

### 4.7 `artifacts::produce` correction loop — unwired

`artifacts/production.rs::produce` (compose → render → re-open → verify → revise,
never overwrite) is called only from `baseline.rs`. The live agent path calls
`agent_runtime::artifacts::create_docx` → `write_document` directly, so a run
gets a single render with a post-hoc check rather than the correction loop.

### 4.8 PPTX — implemented, unreachable

`artifacts/pptx.rs` (560 lines, `write_deck` / `check_deck`) has no tool, no
command and no caller outside its own module. PS 26117 names PPT as a required
deliverable.

### 4.9 Placeholder UI route

`src/App.tsx` routes `/knowledge` to `<Placeholder … phase="Phase 4 — knowledge
service and connectors" />`. The knowledge *backend* exists; the management
surface does not.

### 4.10 Stale drift between layers

Not placeholders, but statements in the tree that are no longer true:

- `orchestrator/runner.rs` returns *"Producing a Word document is not built yet"*
  for `CreateDocx`/`CreateXlsx`. Dead on the agent path — `agent_runtime/mod.rs`
  intercepts both before the runner — but live for any other caller.
- `agent-runtime/src/tools.ts` says the `needsApproval` branch is unreachable
  *"because the approval queue is wired in Phase 4"*. The conclusion is right
  (Rust resolves approval internally and never returns `needsApproval` over the
  wire) but the stated reason is stale: approval **is** wired.
- `sovereignty/broker.rs` comments call the event ring a Phase-1 concern; the
  durable copy exists.

### 4.11 Inherited Sarathi surfaces of unclear standing

- `src-tauri/src/gateway/` — an **unauthenticated axum HTTP server** (OpenAI +
  Anthropic compatible) started unconditionally at app launch (`lib.rs`), bound
  to `127.0.0.1` only, protected by an `Origin`/`Host` guard against drive-by
  browser requests. It reaches `ai_engine::scheduler` **directly and does not
  pass through `ToolGateway` or `PolicyGateway`**, and it starts regardless of
  operating mode. Loopback-only, so not egress — but it is a local API surface
  that bypasses the classification and approval controls.
- `memory_engine/` — 16 submodules, 3 tests, a `MockProvider`, and vendored
  `letta`/`llama_index`/`mem0`/`zep` reference trees under `vendor/`. Standing
  relative to PS 26117 is unclear; it is long-lived state adjacent to
  confidential content.
- `certification.json` / `certification_report.{md,html}` — declares tier
  `"Certified"`, `confidence_score: 92.9`, seventeen sub-scores of which fourteen
  are exactly `92.5`, and a `"signature": "sig_certified_817aa9b8a2ab…"`. Produced
  by a `certification_runner.py` that is not in this repository. This is an
  unverifiable success claim shipped as evidence.
- `src-tauri/tests/verify_*.rs` (5 files) — legacy Sarathi tests requiring real
  downloaded models and containing a hardcoded `C:\Users\lenovo\AppData\Roaming`
  fallback path. **None are in the verify chain.**

Invariants the code enforces today, with where enforcement lives.

|---|---|---|---|
| 1 | Confidential data and network access are never both enabled | `sovereignty/mode.rs` — `permits_network()` and `permits_confidential_data()` are exact complements | Structural |
| 2 | Exactly one module may open an outbound socket | `sovereignty/broker.rs` + `check-egress.mjs` at build time | Structural + CI |
| 3 | Outbound requires https, exact-host allowlist, no redirects | `broker.rs::evaluate` | Structural |
| 4 | Default mode is Work (network refused) | `impl Default for OperatingMode` | Structural |
| 5 | The model can only request; Rust decides | `beforeToolCall` hook → `ToolGateway` → `PolicyGateway` | Structural |
| 6 | An allow is a single-use token bound to exact arguments | `agent_runtime/grants.rs` — SHA-256 args fingerprint, 60s TTL | Structural |
| 7 | Execution re-derives the verdict independently of the grant | `agent_runtime/mod.rs::execute` | Defence in depth |
| 8 | Unreachable gateway blocks the call | `tools.ts::authorizeToolCall` catch → `{ block: true }` | Fail-closed |
| 9 | File access stays inside the run's own workspace | textual `..` resolution in `gateway.rs` + `policy/mod.rs`, refuse-not-clamp | Structural |
| 10 | Retrieval never returns a passage the asker may not see | SQL `classification IN (...)` built from session roles | Structural |
| 11 | Audit log cannot be silently rewritten | SQLite `BEFORE UPDATE/DELETE` triggers + SHA-256 hash chain | Structural + detective |
| 12 | Approver ≠ requester | `Permission::ApproveOutput` withheld from `Administrator`; separation-of-duties check in `policy` | Structural |
| 13 | A rejection must carry a reason | `ApprovalQueue::decide` | Structural |
| 14 | Success requires deterministic evidence, not model prose | artifacts re-opened and checked; verifier resolves citations against retrieved passages | Structural |
| 15 | The agent runtime opens no listening socket and reaches only loopback | `assertLoopback()`; no server in `main.ts` | Structural |
| 16 | stdout carries only frames | `installStdoutGuard()` rebinds `console.*` to stderr | Structural |
| 17 | Tool arguments never travel the event channel | `redactEvent` (TS) + `redact()` (Rust) | Structural |
| 18 | Document text stays out of the durable event stream | `EventDraft::with()` redacts on the way in — no API to bypass | Structural |
| 19 | Side effects happen at most once, across restart | `task_tool_effects` keyed on `(run_id, idempotency_key)` with args fingerprint | Structural *(see caveat)* |
| 20 | No unauthenticated browser page can drive the local model | `gateway/guard.rs` `Origin`/`Host` check | Partial |

### Known weaknesses in the invariant set

- **#19 does not currently fail closed.** `lib.rs` falls back to
  `TaskEventLog::in_memory()` when the durable store cannot open, logging an
  error and continuing. The idempotency table lives in that store, so the
  guarantee silently degrades from "once" to "once per process" — a side effect
  can then repeat after a restart. By contrast `AuditService` does *not*
  `manage()` on failure, so commands depending on it fail at dispatch. The event
  log is the less safe of the two patterns.
- **#20 is partial.** The local gateway is unauthenticated by design (Ollama's
  model). The `Origin`/`Host` guard stops drive-by browser requests but not any
  local process, and requests through it bypass `ToolGateway`/`PolicyGateway`
  entirely (§4.11).
- **Layer-3 injection framing is absent** (§4.4). Layers 1 and 2 hold.

## 7. Current persistence model

### One SQLite database

`<app_data>/sarathi.db`, opened by several modules with independent `rusqlite`
connections plus the `tauri-plugin-sql` migration runner.

| Table | Owner | Notes |
|---|---|---|
| `settings`, `activity_log`, `schema_version` | `database/mod.rs` migrations | inherited |
| `audit_log` | `audit/mod.rs` | append-only by trigger; SHA-256 hash-chained |
| `documents`, `chunks`, `chunk_text` (FTS5) | `knowledge/index.rs`, `documents/store.rs` | classification column drives the ACL filter |
| `models`, `downloads` | registry / download managers | inherited |
| `account_credentials` | `identity/credentials.rs` | Argon2id |
| `memory_nodes`, `working_memory`, `conversation_summaries`, `user_profile`, `projects` | `memory_engine/persistence.rs` | inherited; standing unclear |
| `task_events` | `agent_runtime/events/store.rs` *(uncommitted)* | append-only by trigger; `UNIQUE(run_id, seq)` |
| `task_snapshots` | same | folded cache, rebuildable from events |
| `task_tool_effects` | same | idempotency: `PRIMARY KEY (run_id, idempotency_key)` |

### Files under `<app_data>/`

| Path | Contents |
|---|---|
| `tasks/<run_id>.json` | `TaskRecord` — written **once, when the run ends**. Temp-write + rename, so a crash leaves the old file rather than half a new one. |
| `runs/<run_id>/` | per-run workspace; the only directory a run's tools may touch |
| `documents/` | original bytes (the evidence a citation points at) + derived extractions |
| `models/`, `packs/`, `runtime_profiles/`, `sidecars/` | inherited model and pack storage |

### Two records, deliberately different

- **`TaskRecord` (JSON, once, at the end)** — the readable record: answer, plan,
  routing, evidence excerpts, calculations, tool calls, approvals, artifacts.
- **`task_events` (SQLite, ordered, during)** — the durable history: what a
  window that remounted or a process that just started can read. Redacted:
  identifiers, tool names, outcomes, counters and hashes only.

Compatibility is preserved in both directions: `TaskRecord`'s shape is unchanged,
`tasks::list` still reads it, and history merges records with snapshots — the
record supplies contents, the event history supplies the ending.

### Not persisted (dies with the process)

`RunPlans`, `RunToolCalls`, `RunCalculations`, `RunPassages`, `RunArtifacts`,
`RunWorkspaces` (the table, not the directories), the grant ledger, and the
broker's 512-entry egress ring.

## 10. Risks caused by copied or vendored OpenClaw code

`agent-runtime/vendor/openclaw/` — **286 TypeScript files, 2.9 MB**, pinned to
upstream commit `ed56f3c001a6d18427bc399493edabc7166233bd`, MIT licensed and
recorded in `THIRD_PARTY_NOTICES.md`. Ten packages:

| Package | .ts files |
|---|---|
| `ai` | 152 |
| `normalization-core` | 45 |
| `agent-core` | 36 |
| `model-catalog-core` | 16 |
| `net-policy` | 11 |
| `tool-call-repair` | 9 |
| `llm-core` | 8 |
| `markdown-core`, `media-core`, `retry` | 2 each |

### R1 — Re-sync silently reintroduces cloud providers *(mitigated)*

Pruning provider files by hand is exactly the operation that leaves a dangling
`export * from "./anthropic.js"`. `scripts/audit-vendor.mjs` checks link
integrity, forbidden specifiers (`@anthropic-ai/sdk`, `@google/genai`,
`@mistralai/mistralai`), forbidden modules, and that only `openai-completions` is
registered. `check-bundle.mjs` re-checks the **built artifact**.
**Residual:** both check a known denylist. A provider upstream adds under a new
name that neither list knows about.

### R2 — 286 files of third-party code inside the trust boundary

The vendored tree runs in the same process as the agent loop, and its egress
gate (`net-policy`) is upstream's, not ARJUN's. The Rust-side mitigations are
real (proxy vars stripped, `assertLoopback`, no listening socket, `kill_on_drop`)
but they constrain the *process*, not individual modules within it.
**`check-egress.mjs` covers the ARJUN tree; the vendored tree is audited by a
different script with different rules.**

### R3 — Upstream drift with no re-sync procedure

The pin is recorded; there is no tooling to diff against a newer upstream, no
record of which upstream fixes have been assessed, and no test that would fail if
the pin went stale. Security fixes upstream will not arrive on their own.

### R4 — Modified files carry markers, but nothing enforces them

Changes are marked with an "ARJUN sovereign build" comment and listed in
`agent-runtime/vendor/README.md`. Nothing verifies that every modified file
carries one, or that the README list matches reality.

### R5 — Behaviour ARJUN depends on but does not own

`run.ts` documents this precisely: agent-core's **default** `convertToLlm` drops
everything except user/assistant/tool-result messages, which would silently break
compaction (the summary is a `compactionSummary` message) and interrupt recovery
(the `custom` message warning that tools may have partially executed). ARJUN
passes the harness converter instead. An upstream change to either behaviour
breaks compaction or lets a run repeat a write that already happened — **and both
fail quietly, not loudly.** `compaction.ts` similarly depends on `findCutPoint`,
`generateSummary` and `capCompactionSummary` keeping their semantics.

### R6 — The vendored test suite dominates the signal

`npm run runtime:test` reports 117 files / 1904 tests, the overwhelming majority
upstream's. Only 5 test files are ARJUN's own (`run`, `tools`, `peer`,
`protocol`, `compaction`, `providers`, `hardening`). A reader seeing "1904
passed" may reasonably over-estimate how much of ARJUN is covered.

### R7 — Licence obligations are ongoing

MIT with attribution reproduced. Any future re-sync must re-check that upstream
has not relicensed or added a differently-licensed dependency, and
`THIRD_PARTY_NOTICES.md` must track the new pin.

### R8 — `agent-core` decides loop shape, ARJUN decides authority

Parallel vs. sequential tool execution, steering semantics and abort recovery are
upstream's. ARJUN's authorisation hook is applied per call, so a change in
execution *ordering* cannot widen permissions — but it can change how many calls
are in flight when an abort or an approval lands. The uncommitted event system
records a terminal event that refuses anything after it, which bounds the damage;
it has not been exercised against an upstream change in ordering.
